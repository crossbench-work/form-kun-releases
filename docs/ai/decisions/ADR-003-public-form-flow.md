# ADR-003: 公開フォームフロー（入力 → 確認 → 送信）

## ステータス

採用

## コンテキスト

誤送信を減らし、ユーザーに送信内容を見せたうえで確定させたい。SPA なしで同一フォーム定義を使い回す。

## 決定

- **フロー**: 入力画面 → 確認画面（POST）→ 送信確定（POST）。戻る操作は確認画面から入力へ戻る POST を用意する。
- **検証**: サーバー側バリデーションを正とし、クライアントは補助（`novalidate` と併用する場合は仕様に合わせる）。

## 結果

- 二重送信対策や CAPTCHA はサーバー側のライフサイクルに載せやすい。
- プレビュー専用 DOM と本番 DOM を二重管理する SPA 方式は採用しない（本リポジトリの範囲では「プレビュー」は別 URL の公開フォーム表示に寄せる）。
